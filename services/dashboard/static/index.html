CALIPERlocal stack

Servizi

Ordinati per livello di pipeline (L1 in alto). Stato letto lato server ogni 8s; log in sola lettura via un proxy Docker con permessi solo GET — nessun controllo di avvio/stop/restart in questa pagina.

    Rete

    Isolata dove non serve comunicazione, condivisa dove serve.

    caliper-ai

    ollama, qdrant, flowise, stream-agent, verifier, open-webui. Comunicano davvero fra loro.

    caliper-public

    solo questa dashboard. Eccezione multi-homed dello stack: sta anche su caliper-ai perche' deve leggere lo stato degli altri servizi e i log tramite il proxy Docker — non e' piu' una pagina puramente statica.

    docker-socket-proxy

    unico punto che tocca /var/run/docker.sock. Espone solo GET su /containers (lista, inspect, log) — POST=0 blocca ogni azione di scrittura, niente start/stop/restart/exec, per scelta esplicita, non solo perche' la UI non li mostra.

    verifier-executor / prusaslicer

    network_mode: none — nessuna rete ne' in ne' out. Il verifier-executor esegue codice generato da un LLM (non fidato per definizione) e comunica col verifier solo tramite un volume condiviso, mai HTTP diretto.

    Capacity

    Stime, valide solo eseguendo lo stack in locale.

    ~13 GB di pull immagini compresse (~18–21 GB estratte/in esecuzione), dominato da ollama, open-webui e verifier-executor (CadQuery/OCP/VTK, ~2.8 GB).

    RAM: 5–8 GB di picco su tutti i container piu' i due modelli locali (granite4:1b, granite-embedding:30m); +1–2 GB transitori quando verifier-executor esegue un job (limite 2 GB per job via RLIMIT_AS).

    VRAM: ~2.5–3.5 GB per gli stessi modelli.

    Installazione

    Versione breve — dettaglio completo nel README, sezione 9.

    • Docker Desktop/Engine + Compose v2, GPU NVIDIA opzionale per Ollama
    • Copiare .env.example in .env e compilare
    • docker compose up -d
    • docker compose exec ollama ollama pull granite4:1b e granite-embedding:30m
    • Creare un account Flowise, generare una API key, poi docker compose up flowise-init
